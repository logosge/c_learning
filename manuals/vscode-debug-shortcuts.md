# VSCode + C 调试快捷键速查

> 适用环境:Windows + VSCode + gcc/gdb(MSYS2 UCRT64 工具链)
> 建库日期:2026-11-05
> 键位为 VSCode 默认值;若改过键位,用 `Ctrl+K Ctrl+S` 查当前绑定。

---

## 一、启动与停止

| 键 | 作用 |
|---|---|
| `F5` | 启动调试 / 继续运行到下一个断点 |
| `Ctrl+F5` | 不调试直接运行(编译后执行) |
| `Shift+F5` | 停止调试 |
| `Ctrl+Shift+F5` | 重启调试(改完代码不用手动停再开) |
| `Ctrl+Shift+D` | 打开「运行和调试」视图 |
| `Ctrl+Shift+Y` | 打开调试控制台(Debug Console) |

---

## 二、单步执行(最常用)

| 键 | 名称 | 干什么 |
|---|---|---|
| `F10` | Step Over 单步跳过 | 执行一行;遇到函数调用**不进去** |
| `F11` | Step Into 单步进入 | 执行一行;遇到函数**就进去** |
| `Shift+F11` | Step Out 单步跳出 | 把当前函数**跑完**回到调用处 |
| `F5` | Continue | 直接跑到下一个断点 |

**判断用哪个**:

- 这行是 `printf(...)` / 库函数 → 按 **F10**(没必要看库内部)
- 这行是**自己写的函数**,想看内部 → 按 **F11**
- 进错了想出来 → `Shift+F11`

---

## 三、断点

| 操作 | 方式 |
|---|---|
| 加 / 删断点 | `F9`,或点行号左侧空白 |
| **条件断点** | 右键行号 → 添加条件断点 → 写 `i == 100` |
| **日志断点** | 右键行号 → 添加日志断点 → 写 `i is {i}`(不暂停,只打印) |
| 启用 / 禁用断点 | 调试侧栏 BREAKPOINTS 里的勾选框 |

> **条件断点是调试循环的关键**。循环 1000 次只有第 800 次出错,就加条件 `i == 800`,不用手动按 800 次 F5。
>
> **日志断点**适合"想知道每次循环的值,但不想每次停下来"的场景——它只打印,不中断。

---

## 四、查看数据

| 位置 / 操作 | 作用 |
|---|---|
| 鼠标悬停变量 | 显示当前值(**必须已启动调试**,否则显示的是编译时值) |
| 侧栏 VARIABLES | 展开看局部变量、全局变量、指针 |
| 侧栏 WATCH | 手动加表达式,如 `arr[i]`、`p->next`,会跟着刷新 |
| 侧栏 CALL STACK | 调用栈——看清"是谁调用了这个函数" |

## 五、调试控制台直接调 gdb

在 Debug Console 里用 `-exec` 前缀,等于直接执行 gdb 命令:

| 命令 | 作用 |
|---|---|
| `-exec p i` | 打印变量 `i` |
| `-exec p *ptr` | 解引用,看指针指向的内容 |
| `-exec p arr[2]@5` | 从 `arr[2]` 开始打印 5 个元素 |
| `-exec x/10d arr` | 以十进制查看数组前 10 个元素 |
| `-exec bt` | 打印完整调用栈 |
| `-exec info locals` | 列出所有局部变量 |
| `-exec watch count` | 监视变量,值一变就暂停 |
| `-exec set var i = 100` | **运行时改变量值**(不用改代码重编译) |
| `-exec info breakpoints` | 列出所有断点 |

> `-exec set var` 最实用:想测某个边界条件,不必改源码重编译,调试时直接把变量改成那个值。

## 六、本项目相关排查

本项目 `.vscode/launch.json` 使用 **`process` 模式 + gdb 绝对路径**。

| 现象 | 检查 |
|---|---|
| `F5` 起不来 | 看调试控制台是否报 `miDebuggerPath` 相关错误——通常是 gdb 路径写错 |
| 断点显示为**空心圆**(灰色) | gdb 没加载到符号表 → 确认 `tasks.json` 编译参数带了 **`-g`** |
| 修改代码后调试的是旧程序 | `launch.json` 若配了 `preLaunchTask`,F5 会先自动编译;没有就要手动执行构建任务 |
| 程序一闪而过 | 不是调试问题——`Ctrl+F5` 直接运行不带暂停,用 `F5` 或在 `main` 末尾加断点 |
